## 音频失败与后续定位

Smoke 失败后读取系统负载约 97%，后台有模拟器和游戏客户端活动；没有关闭它们。失败发生在独立音频 helper 中，主 GUI 已关闭。本版没有修改混音、重采样或 WASAPI 引擎。高负载可能相关，但尚未完成低负载对照，不能断言它是唯一原因。

Soak 失败时音乐输入欠载和丢帧计数均为 0，麦克风累计欠载 100 帧，虚拟线路捕获报告不连续。还需区分自建测试音源、混音调度、虚拟线路和观测端的调度问题。测试音源与观察线程的调度健壮性也应检查；不要通过降低断音阈值或无限重跑来制造通过。

下一轮优先让用户自行暂停高占用任务，然后在一致设备与音量下对照 Smoke / Soak，保留全部结果；再确认网易云连续实播。频响幅度通过不代表连续性、THD、真人双讲或听感已通过。
