机器可读的测试结果和对应 EXE 哈希见 `test-results/windows-runtime-0.1.0.json`。打包脚本只有在记录中的 EXE 哈希与当前产物一致且界面、音频检查通过时，才会在 build-info.json 中标记 windows_runtime_tested。网易云实播日志为 player.log/player.json，界面证据为 gui-player-exercise.log/gui-player-running.png。原始日志和窗口截图保留于 Fedora 的 `~/.local/state/partymic/remote-20261018/`，未包含麦克风录音。

测试不启动、注入或操作游戏与反作弊程序。GUI 测试只向 PartyMic 自己的窗口发送控件消息；驱动安装使用官方安装器。未使用 RDP 的音频重定向代替 Brio 90，未关闭反作弊服务、启用测试签名或自动重启 Windows。驱动安装后的默认普通录音设备是 CABLE Output，默认通信录音设备仍为 Brio 90；默认播放和默认通信播放均为原有 Mi Monitor，不是虚拟线路。实际开黑前应将播放及语音输出设为耳机，避免实体麦克风收回扬声器声音。

重启后的首次增益检查未通过：原测试对整段音频做相干频谱累加，相位变化会使该值抵消。已用人工构造的相位翻转信号验证分段频谱测量，并改用 RMS 比值检验增益。随后增加逐样本统计，发现过约 10 ms 的静音缺口和停止后的短残留；现已加入输入预填充、MMCSS 调度及停止时补写静音/重置缓冲。追加连续测试在约 46 秒时仍失败，因此进一步加入两路输入各自的小幅自适应线性重采样以保持缓冲余量，并增加模拟快慢时钟的核心测试。初始失败日志均保留；未通过放宽静音缺口或停止阈值处理。最终版本重新通过完整启停、界面及 90 秒连续混音测试。最终检查结果及对应 EXE 哈希以 test-results/windows-runtime-0.1.0.json 为准。

复现 Fedora 编译与打包：

```bash
bash scripts/build-windows.sh /tmp/llvm-mingw-20260616-ucrt-ubuntu-22.04-x86_64
```

Windows 交互桌面运行硬件测试（会播放短暂低音量测试音并打开 Brio 90，不保存录音）：

```powershell
.\windows_audio_smoke.exe --run
```

还可运行 `windows_audio_smoke.exe --soak 90`，或在网易云播放时运行 `windows_audio_smoke.exe --player cloudmusic.exe 60`。可通过源码包中的 `scripts/run-windows-audio-test.ps1` 保存 UTF-8 日志及 EXE 哈希。

跨平台核心测试与硬件测试相互独立。后续完整人工验收清单见 windows-validation.md。
