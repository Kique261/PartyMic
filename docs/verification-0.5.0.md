## 实际线路幅度测量

自建正弦幅度 0.025，理论 RMS 为 `0.025 / sqrt(2)`。每频点独立启动音源、预热，采集稳定窗口，仅计算幅度和缓冲计数：

| 频率 | CABLE Output RMS | 相对理论幅度 |
| --- | ---: | ---: |
| 1 kHz | 0.0176770 | −0.000339 dB |
| 8 kHz | 0.0176777 | +0.000008 dB |
| 12 kHz | 0.0176774 | −0.000111 dB |
| 16 kHz | 0.0176774 | −0.000153 dB |
| 20 kHz | 0.0176806 | +0.001427 dB |

所有频点均无输入丢帧或音乐欠载。这不包含 HDMI 模拟输出、房间拾音、客户端编码，不是 THD、相位或听感测试。原线性插值的独立队列诊断曾测得 16 kHz 约 −3.01 dB、20 kHz 约 −4.22 dB；旧诊断与本表的测量路径不同，不能将两表直接当成受控真机前后 A/B。

## 发现并保留的失败

开发初始核心测试要求输出始终位于输入最小/最大值之间，与有启动延时和振铃的带限滤波不相容。现改用连续低频信号的稳定范围、频响、双声道和缓冲约束，而不是简单删除检查；还修复了溢出时旧滤波历史未清理的问题。

第一版淡入候选的录音试听和布局通过，视觉测试发现下拉框焦点通知取消了尚在准备的覆盖层。修正后，最终哈希完整 GUI 复验通过。失败候选 EXE 和 `gui-tests-run1` 原日志保留，最终结果位于 `gui-tests-run2`。

附加 ASan/UBSan 配置未能完成：Fedora 缺少 `/usr/lib64/libasan.so.8.0.0`，编译器链接自检失败。本次没有 sanitizer 通过记录，普通 Release 核心测试通过。

网易云的静音失败同样保留在 `extra-tests`，不能写成该项通过；需在确认实际播放后重新验证。
