# 音质、录音与试听排查

适用 0.5.0。实际测试范围见 [verification.md](verification.md)。

## 讲话后音乐发闷、忽大忽小

先关闭“说话时自动压低音乐”。新版默认关闭；需要突出人声时再开启，并从“保留音乐 65%”开始比较，100% 表示不衰减。旧版固定保留 25%，约减少 12 dB，不代表改了音乐编码或采样率，但会显著改变平衡。

将“人声音量”先设为 100% 或更低，避免高增益使混音触发软限幅。录一段“仅人声”，若不讲话时仍听到明显音乐，说明麦克风拾到了音响。再用耳机重复同一测试，比较音色、回声和音乐层次；当前没有软件声学回声消除，不能宣称单靠更换压低系数就能消除房间拾音。

如果本地 WAV 清楚，只有语音客户端中的音乐失真，检查该客户端的降噪、自动增益、语音活动门限与音乐模式；必要时做受控开关对比。不要因此修改 ACE 或注入游戏。

## 不讲话时内录音乐仍不清晰

0.5.0 已替换时钟校正中的线性插值，修复在独立队列测量中发现的高频衰减。实际进程采集 → 混音 → VB-CABLE 的低音量合成正弦测试中，1–20 kHz 幅度误差小于 0.002 dB；这不代表完整频谱、失真、相位或真人听感全部通过。

可先记录当前人声音量/静音状态，临时勾选“静音麦克风”，录制同一段“音乐 + 人声”，得到仅含数字音乐的对照，再恢复原设置录制混合版本。若只有恢复麦克风后发闷，暂停音乐并录“仅人声”确认是否拾入外放，再用耳机重复。比较时保持音乐增益、片段和试听输出一致，避免触发限幅。当前尚未内置单独的“仅音乐”录音选项。

Brio 端点的私有流能力探测报告 Other 类别下已有降噪、AEC 关闭，Communications 类别下 AEC 开启；这是探测流的效果状态，不能直接视作 PartyMic 已启用消回声，也不能证明整个听感问题来自该处理。完整测量范围见 [验证记录](verification.md)。

## 调整人声音量并试听

1. 暂停外放音乐，实体麦克风选择 Brio 90，调整“人声音量”（0–200%）。这影响录音和混音，不改变系统麦克风属性。
2. 点击侧栏“录音与试听”，选择“仅人声”，点击“录制 15 秒”，正常讲话。可随时点击“停止录音/试听”提前保存。
3. 试听输出选择实际设备，例如 `Mi Monitor (NVIDIA High Definition Audio)`；在当前机器上它经 HDMI 到显示器，再经 3.5 mm 到音响。
4. 点击“试听刚才录音”；程序会先停止混音。可调“试听音量”，也可以打开文件夹，用系统播放器播放 WAV。录音保存在桌面 `PartyMic录音` 文件夹。
5. 比较不同人声音量时重新录音；试听音量只改变回放，不会更改已保存文件。重新开始混音需要手动点击“开始混音”。

验证音乐叠加时先播放网易云并开始混音，然后选择“音乐 + 人声”录音。这保存实际 CABLE Output，不是播放设备的整体声音。多人通话前可先用客户端的麦克风测试确认选择的是 `CABLE Output`。

## 提示音能听到，但回放很轻或听不到

检查“试听输出”明确选中了 HDMI、耳机或音响，且设备没有静音，试听音量非零，录音时人声音量非零且未勾选静音麦克风。先暂停网易云再试听，避免正在播放的歌掩盖录音。WAV 为 16 bit PCM，不需要额外解码器。

历史测试中 `PlaySound` 返回成功并不意味着用户实际听到；因此新版使用明确设备 ID 的 WASAPI 回放。日志“播放完成”只能证明提交和排空成功，听感仍需用户确认。不要仅凭状态文字宣布主观音质通过。

## 未找到音源或不能录混音

网易云至少播放一次后刷新。仅人声录音不依赖音乐会话或 VB-CABLE；混音录音需要先开始混音，且当前仅支持标准官方立体声 `CABLE Input` / `CABLE Output`。不要选择 `CABLE In 16ch`，不要把 Windows 默认播放或通信播放设为虚拟线路。

没有设备权限、设备拔出或格式不支持时会显示失败原因。停止后重新插入设备并刷新；不要让多个测试程序与 PartyMic 同时输出到同一条虚拟线路。
