# 界面设计与维护（0.5.0）

0.5.0 已将切页的逐帧原生控件位移替换为内容快照淡入；原有悬停、开关、电平及滚动修复继续保留。真实绘制计时和限制见 [当前验证记录](verification.md)。

PartyMic 使用原生 Win32 控件与 GDI+ 绘制，保留现有混音和录音线程。浅灰侧栏、橙色主操作、青绿色选中态、白色圆角卡片参考 CC Switch。波形标志和线条图标由本项目自行绘制，没有复制其应用标识、图片或 React 组件代码。

## 代码入口

- `src/windows/ui_theme.h`：集中颜色、图标与控件类型。
- `src/windows/ui_theme.cpp`：圆角、抗锯齿线条、按钮、复选框、滑块、下拉框、电平条；用 `SetWindowSubclass` 限定到本进程控件，释放时移除。
- `src/windows/page_transition.h/.cpp`：捕获本程序内容区，管理短时覆盖层与双页面淡入，释放位图、DC 和窗口。
- `src/windows/main.cpp`：页面导航、状态绑定、逻辑坐标与宽度锚点。设计宽 1120，侧栏 220，页头 110；缩小时滚动内容，背景绘制裁剪到页头下方，越过页头的控件整项隐藏，避免原生组合框打印时忽略局部区域。

页面掩码：混音 1，录音 2，指南 4，公共导航 7；人声滑块/数值/静音为 3，切页移动同一控件，避免产生两套增益状态。导航 ID 201–203，音频控件沿用 101–119。新增按钮需同步 GUI 自动化。

按钮和下拉框继续使用原生点击、键盘、焦点和勾选语义；滑块输入与绘制统一由主题处理，保留原生数值和通知。`CBS_OWNERDRAWFIXED` 统一下拉项；颜色不能成为唯一的状态提示。GDI+ 是系统 DLL；头文件须先包含 `windows.h`、`propidl.h` 再包含 `gdiplus.h`，避免 LLVM-MinGW 的 PROPID 声明问题。

## 修改后的检查

编译后执行核心 CTest，在 Windows 交互桌面运行 `test-windows-preview-ui.ps1`，检查三页切换、共享音量、录音保存和试听；使用 `test-windows-layout.ps1` 检查原生下拉、鼠标/键盘滑块、缩小滚动和页面截图。每次记录实际 EXE 哈希；多显示器 DPI 切换与屏幕阅读器体验仍需人工验收。发行包不得包含测试录音或完整桌面截图。

控件消息必须按 `Kind` 判定：不同 Win32 控件重用 `WM_USER` 偏移，例如 `TBM_GETRANGEMAX` 与 `PBM_SETPOS` 数值相同；不能统一按消息号触发重绘，否则滑块绘制会反复使自身失效并饿死计时器。

## 0.4.0 图标与动效

图标采用原创橙色渐变圆角底、白色麦克风和两侧声波，以及青绿色点缀。`src/windows/assets/partymic.svg` 为可编辑矢量稿，PNG 供预览，ICO 包含 16、20、24、32、40、48、64、96、128、256 共 10 档尺寸。用 `python3 scripts/generate-icon.py` 重建三种资产，开发环境需 Pillow，Windows 运行时无需该依赖。

`app.rc` 将 ICO 内嵌为资源 101；`main.cpp` 同时设置窗口大小图标，并将相同图标用于侧栏。DPI 改变时按新尺寸加载资源，替换后释放旧图标；类图标使用资源的共享句柄。桌面快捷方式使用发行 EXE 的第一个图标，使用新的版本路径避免沿用旧版图标缓存。CMake 为 RC 添加 ICO 的显式构建依赖。

过渡使用 UI 线程的短时 Win32 定时器与缓出插值：悬停约 160 ms、侧栏选中/开关约 180 ms、按压 80 ms、页面内容淡入 200 ms、状态变化提示 360 ms；电平条上升 80 ms、回落 240 ms。电平平滑仅改变显示，不影响真实增益或音频。页面切换不中断采集。没有循环呼吸灯、后台动画线程或系统级高频计时设置。

读取 Windows `SPI_GETCLIENTAREAANIMATION` 与 `SPI_GETUIEFFECTS`，在设置变动时刷新；关闭动画时直接显示最终状态。过渡结束立即取消其定时器，隐藏/最小化时收敛；静止电平不重复使控件失效。动效期间不插入输入等待。

## 滑块残影与滚动闪烁

原生 trackbar 的输入处理可能直接绘制系统滑块，而主题另在 `WM_PAINT` 绘制圆形滑块，快速滚轮或拖动会留下两套图形。现在滑块保留原生数值、范围、控件类型和可访问接口，由主题统一处理指针捕获、键盘、滚轮并发送普通 `WM_HSCROLL` 通知；不调用会直接画原生滑块的默认输入路径。程序性 `TBM_SETPOS` 同样重绘主题。高精度滚轮余量累计到完整刻度；控件上的滚轮只改变该控件，不滚动页面。

父窗口使用 `WS_CLIPCHILDREN`，控件使用 `WS_CLIPSIBLINGS`；页面位置和显示状态通过 `DeferWindowPos` 批量提交，禁用旧位置像素拷贝和中间重绘，最后统一重绘。滚出页头的控件不会先显示再隐藏；下拉项高度仅在尺寸改变时设置。`WM_PAINT`、`WM_PRINTCLIENT`、`WM_PRINT` 共享主题缓冲绘制，保证实际画面与捕获画面一致。

`scripts/test-windows-visual.ps1` 在目标进程窗口内验证图标资源、页面控件位置固定、覆盖层释放、绘制帧间隔、过渡中调音量、悬停中间色、两路快速滚轮/高精度滚轮/连续拖动、不误滚页面、实际滑块画面与干净绘制对比、反复切页后 GDI 数量和空闲 CPU；会短暂移动鼠标并恢复原位置。辅助截图只截本程序或本程序控件，不采集完整桌面。系统关闭动效的分支及多显示器 DPI 切换仍需单独验收。


## 0.5.0 页面淡入与性能边界

切页前捕获当前内容画面，真实控件直接布局到最终位置，捕获新页后由透明命中测试的子窗口绘制两张位图的淡入。固定侧栏与页头立即更新。中断时先取当前合成画面作为下次过渡起点，避免跳回上一页。只捕获本程序的客户区和子控件，不捕获其他应用或完整桌面。

逐帧只执行 BitBlt / AlphaBlend，不调用整页 `position_controls`。主过渡定时器请求间隔 10 ms，以经过时间计算缓出进度，200 ms 后停止；Win32 定时器仍受系统调度影响，不承诺显示器同步。`msimg32.dll` 是系统依赖，构建和打包白名单已同步。

普通点击、选择、调音量、滚动、缩放或 DPI 改变会结束过渡，显示实时控件；下拉框焦点通知不得取消尚在准备的画面。界面测试首次发现这一问题，修复后在最终 EXE 重跑完整录音试听、布局与视觉检查。窗口属性 `PartyMicTransitionFrames`、`PartyMicTransitionMaxGapMs`、`PartyMicTransitionDurationMs` 只保存上次过渡的本窗口绘制计数，便于回归，不涉及钩子或系统采样。

本次四段无截图干扰的过渡测得 10–13 次 WM_PAINT，最大绘制间隔 16–32 ms，持续 203–204 ms；切页命令含两次快照和一次布局耗时约 62–85 ms。该数据不是 DWM 呈现帧率或固定 60 FPS 保证。后续可继续减少快照准备耗时；多显示器、系统关闭动画与不同刷新率仍需人工验收。


## 0.5.1 未发布修复候选

0.5.0 的实际切页仍会闪烁，原因是目标控件先绘制到屏幕，再盖上旧页快照淡入。候选现在在 `prepare` 就显示固定旧页遮挡，目标布局和快照在遮挡下完成，`start` 才开始淡入；快速导航复用覆盖层。主窗口启用 `WS_EX_COMPOSITED` 进行窗口树合成。四组实际屏幕序列暂未检出倒退，但准备耗时及帧间隔较高，不能称为流畅度已完成；详见 [交接](handoff-2026-10-18.md)。
